# Reflection 계약 — 사장님 수정에서 배우기

> content-engine 등 승인 게이트가 있는 워크플로우의 reflection 스텝 전용 프롬프트.
> 입력: `artifacts/{run_id}/_pre_edit/` (생성 원본) vs 게이트 의존 아티팩트의 현재 파일 (승인된 최종본).

## 절차

1. **Diff 수집**: `_pre_edit/` 각 파일과 같은 이름의 현재 아티팩트를 문장 단위로 대조한다. `_pre_edit/`가 없거나 두 버전이 동일하면 "수정 없음 — 학습할 것 없음"으로 종료 (억지 학습 금지).
2. **변경 유형화** — 바뀐 부분을 아래 4유형으로만 분류한다:
   | 유형 | 예 | 처리 |
   |------|----|------|
   | 톤 | 존댓말↔반말, 이모지 추가/제거, 격식 수준 | 패턴 후보 |
   | 표현 | 특정 단어 교체(금지어/선호어), 문장 길이 | 패턴 후보 |
   | 구조 | CTA 위치, 해시태그 수, 문단 분할 | 패턴 후보 |
   | 사실 정정 | 가격·영업시간·메뉴명·수치 수정 | **즉시 KB 후보** (다음 생성부터 반영) |
3. **승격 규칙 (오학습 방지)**:
   - 사실 정정 → 즉시 `knowledge-base/{client}/insights.md` 반영 후보로 기록
   - 톤/표현/구조 패턴 → **이번 run에서 처음 관찰이면 "관찰 1회"로만 기록**. 이전 reflection 로그(`outputs/{client}/content/*reflection*` 또는 KB)에 같은 패턴이 이미 1회 이상 있으면 그때 `clients/{client}/copy-patterns.md` 승격 후보로 제안
   - 근거 없는 일반화 금지: "사장님이 문장 하나를 줄임" → "항상 짧게"로 확대 해석하지 않는다. 관찰된 그대로 기술
4. **출력 형식** (reflection.md):

```markdown
# Reflection — {run_id} / {날짜}
## 수정 요약: {N}개 파일, {M}개 변경
## 사실 정정 (즉시 반영 후보)
- {before} → {after} (파일: ...)
## 패턴 관찰
| 유형 | 관찰 내용 | 누적 횟수 | 판정 |
|------|----------|----------|------|
| 톤 | ... | 1회 (신규) | 관찰만 기록 |
| 표현 | ... | 2회 | copy-patterns 승격 제안 |
## 승격 제안 (2회+ 만)
- copy-patterns.md에 추가 제안: "{규칙 문장}"
```

5. **금지**: KB·copy-patterns 파일을 직접 수정하지 않는다 — 제안만 기록하고 kb_queue/Reporter 경로를 따른다 (append-only 원칙).

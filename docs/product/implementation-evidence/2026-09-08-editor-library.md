# 웹 재작성·사진·보관함 구현 증거

## 한 장 요약

기존 텍스트 편집에 실제 사진 업로드, 명시 재작성과 작업 보관함을 연결했다.
사장님은 같은 사진과 저장된 수정본을 기준으로 새 문안을 요청하고, 별도 확인·최종 검토 후 정확한 파일을 저장한다.
이 문서는 로컬 기술 검증을 기록한다. 실제 공급자 품질·고객 사용성·유료 운영·G02 적용 판단은 OPEN이다.

## 구현과 확인 경계

| 경로 | 구현과 검증 대상 |
|---|---|
| 사진 입력 | JPEG/PNG 1장, 20 MiB·24MP·단일 프레임. 기존 EXIF 방향/축소/메타데이터 제거와 가게별 해시 경로를 재사용. 설명·권리·개인정보 확인 필수. 원본 파일명 미보관. |
| 사진 표시·승인 | 인증과 가게 소유권을 먼저 확인. 생성된 run의 입력과 Job 입력 전체를 대조하고 실제 PNG 바이트를 검증. 표시 사진과 승인 manifest가 달라지면 차단. 미리보기는 private/no-store. |
| 재작성 | 승인 전 한 가지 사실의 웹 작업에서 수정본 저장→취소 완료→짧게/친근하게/가격·기간·혜택 수정→새 요청 미리보기→사용량 확인→새 Job. 원본·수정본·사진을 덮어쓰지 않음. |
| 출처·중복 요청 | 원본 run/EditBase/revision/문안 SHA와 새 사실 SHA·확인자·사진 manifest를 서명에 고정. 같은 확인 토큰은 같은 Job. 토큰 만료 1시간, 큰 한글 문안은 압축 서명 사용. |
| 생성·한도 | 기존 worker/생성 명령/상품 한도/사장님 승인/terminal reviewer를 사용. 미리보기는 생성하지 않음. 취소된 작업의 이미 사용한 작성 시도는 반환하지 않음. 실제 공급자 비용은 별도. |
| 보관함 | 허용된 가게·상태·한국 시간 날짜 범위만 조회. 양끝 날짜 포함, 최신 시각과 PK로 안정적 정렬, 20건 페이지 이동 및 필터 유지. 빈 결과·잘못된 날짜/페이지 안내. |

## 통합 리뷰에서 수정한 결함

1. 재작성 JSON의 중복 키 앞에 숨긴 원문이 Pydantic의 마지막 값 파싱 뒤에도 보존될 수 있었다. 바깥 JSON과 기준 문안 모두 중복 키를 거부하고 보존 원문에서 비밀값을 검사한다. 형식이 유효한 해시·실행 번호에는 전화번호 마스킹을 적용하지 않는다.
2. 사진 표시가 Job 입력, 승인 해시가 엔진 입력을 따르던 불일치를 막았다. 유효한 다른 사진 manifest로 바뀌어도 표시·승인 전에 거절한다. worker의 기존 입력 대조도 유지한다.
3. 사진 오류 화면에서 설명의 비밀값이 다시 표시되는 문제를 공통 PackForm 입력 경계에서 수정했다. 사실·리뷰·설명은 기존 bounded/secret-aware 정리 규칙을 공유하고, 식별자는 Django 필드 형식 검증으로 보존한다. 안전한 다른 입력은 유지한다.

## 실제 로컬 브라우저 증거

`artifacts/real-use-review/g20-synthetic-v3/evidence.json`에 390/1280px Chromium 흐름과 화면 20장을 기록했다.
JPEG 업로드→정규화 사진 표시→원본 수정본 저장→취소→friendly 새 요청→키보드 사용량 확인→새 수정본 확인→최종 ZIP을 실행했다.
캡처 전에 이미지 decode를 기다렸으며 가로 넘침, 보관함 정상/빈 결과/잘못된 날짜 400을 확인했다.

- 원본: `web-b7e7057a0e8042828c97c1b5035570ba`, cancelled. 저장된 수정본 보존.
- 새 실행: `web-f2f2e722baad4b248286b48523e8c0c2`, success.
- 사진 SHA-256: `ec472a0bc46272a63cbf19686ca5d4d226d8175dd3ed0016b56299f87bc925dd`.
- ZIP SHA-256: `8fd8a605e7d33d43bcc021b5b7f397c90cddbce64c60a98af8dae660f2a26da6`.
- 작성 시도 2회, 납품 1건, 취소한 팩 예약 1건 해제. 합성 생성·검토 명령만 사용했다.

v1의 선택자 오류와 v2의 이미지 decode 전 캡처를 보존하며 최종 증거는 v3다. 최종 PackForm 보완 뒤 회귀 결과는 아래 검증 기록에서 구분한다.

추가 `g20-reflow/evidence.json`과 6개 최종 화면에서 390/1280px, root 글자 18→36px 확대와 1,200자 문안의 가로 넘침·가림·키보드 이동을 확인했다. 글자 확대는 CSS 검사이며 OS/브라우저 배율 검사가 아니다. 긴 문안은 DOM에만 넣은 합성 스트레스 입력으로 원본 파일·Job을 바꾸지 않았다. H1의 높이 차이 2px는 overflow:visible인 글꼴 경계로 실제 가림이 없음을 화면과 계산 스타일로 확인했다.

## 검증 기록

- 독립 사진·보관함 wrapper 2개 통과(29.56초), 재작성 core·웹 4개 통과(145.48초).
- root 재작성 core 3개 통과(27.96초): 새 사실의 기존 생성/검토/ZIP 연결, 사실 해시 불일치, 전화번호 모양 해시 보존, 중복 JSON 원문 차단.
- 최종 PackForm 사진/입력 Django 9개 통과(24.587초): 비밀값·제어문자·초과 입력의 오류 HTML 미반사, 서비스 실패 입력 보존, PII 최소화, 식별자 유지, unknown/duplicate POST 거부.
- 저장소 전체 Ruff·basedpyright, Django check --deploy 및 migration consistency 통과. wheel의 변경된 모듈/템플릿 9개를 현재 source와 바이트 대조했다.
- 최종 전체 회귀: **592 passed, 1 skipped, 2009.60초**. skip은 `tests/test_feedback_storage.py:132`의 Windows 파일 symlink 생성 권한이며 실제 junction 거부 검사는 통과했다.
- 최종 독립 reviewer는 전체 종료 로그, 현재 코드, P1 재현 해결, ZIP/사진/bundle 및 확대 화면을 확인해 **G20 D 기술 범위 PASS**로 판정했다. 보고서는 로컬 `artifacts/real-use-review/g20-review.md`에 보관한다. G02·실제 고객·공개 운영·전체 Goal의 완료 판정은 아니다.

## 운영 한계

현재 재작성은 승인 전 취소된 한 가지 사실의 웹 작업에 한정한다. 사진 교체는 새 소식 요청이다.
모델이 실제로 좋은 문안을 쓰는지, 실제 한국어 IME·보조기기·사장님 과제 성공 여부는 별도 관찰이 필요하다.
사진의 개인정보 픽셀 제거·권리 진위 판단·자동 삭제·공급자 삭제는 제공하지 않는다. 미채택 정규화 사진도 보관 정책 확정 전 임의 삭제하지 않는다.
workflow/프롬프트 변경 전 기존 버전에서 진행 작업을 완료하거나 취소해야 한다. 고정 명세 해시를 강제로 바꾸지 않는다.

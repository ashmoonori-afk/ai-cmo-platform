# 오늘 할 일과 쉬운 생성 진입 검증

## 한 장 요약

가게 목적·시간을 참고하는 세 개의 준비 카드와 신메뉴·영업/휴무·행사·리뷰 입력 도움말을 기존 Django 앱에 연결했다.
진행 중인 작업을 우선 표시하고, 원장을 수정하지 않는 사용 가능 건수 안내와 접수 시 재확인을 추가했다.
새 모델·워크플로우·의존성은 추가하지 않았다. G02·실제 고객 사용성·공개 유료 운영은 OPEN이다.
사용 방법과 운영 경계는 [STORE_APP](../../STORE_APP.md)을 따른다.

## 구현과 수정

| 경계 | 동작과 검증 |
|---|---|
| 가게 원천 | 소유권을 확인한 Store의 안전한 client ID로 config.md만 읽는다. 경로 재지정·비정규 파일·64KiB 초과·잘못된 UTF-8·숨은 문자·중복 필드·미지원 스키마는 기본 안내로 전환한다. 목적 세 값과 5~240분만 사용하며 draft나 대표 상품을 이번 주 사실로 복사하지 않는다. |
| 오늘 할 일 | 목적에 따라 세 카드의 순서를 정하고 시간에 따라 리뷰 최대 2/5개와 사진 없는 소식 1건을 안내한다. 새 소식이 없는 날은 생성할 필요가 없다고 안내한다. |
| 소식 종류 | 다섯 가지 허용된 intent는 폼 도움말만 바꾼다. 서버의 가게·실행 정책·한도를 선택할 수 없다. 리뷰 전용 기능이 없음을 표시하고 실제 소식은 필수로 받는다. |
| 진행 중 작업 | queued/running/waiting_approval 및 취소 대기 작업을 우선한다. 새 요청 GET/POST는 기존 작업으로 이동한다. 동시 접수는 기존 DB 제약으로 보호한다. |
| 사용 건수 | 원장 없음·제한 미설정·이번 달 한도 미설정·조회 실패·잔량 부족을 구분한다. 조회는 DB를 생성하거나 migrate하지 않는다. 남은 건수는 한도에서 예약/사용을 빼고, 작성 시도는 별도로 표시한다. |
| 접수와 재전송 | 접수 시 최신 한도를 재확인하되 worker의 권위 있는 예약 검사를 유지한다. 완료한 동일 제출 키/입력의 재전송은 한도 소진이나 서비스 설정 제거 뒤에도 기존 작업을 반환한다. 동일 키의 다른 입력은 거부한다. |
| 실패 안내 | 한도 조회가 실패하면 새 요청을 막고 운영자 문의를 표시한다. 실패한 작업에서도 현재 건수 안내를 제공하되 이를 실패 원인으로 단정하지 않는다. 승인·저장은 별도 기존 검증을 따른다. |

독립 리뷰에서 일부 열이 없는 이전 quota schema가 `IndexError`를 내어 홈/작성 화면을 500으로 만드는 경우를 재현했다.
읽기 경계에서 구조 접근 오류도 고정된 조회 실패 안내로 처리하고, 부분 schema의 GET 성공과 DB 바이트 불변 검사를 추가했다.
테스트용 SQLite 연결은 명시적으로 닫아 Windows 파일 정리 시 잠금이 남지 않도록 했다.
기존 WAL DB의 읽기 전용 연결도 SQLite의 `-wal`/`-shm` 보조 파일을 만들 수 있다. 여기서 읽기 전용은 DB 본문·스키마·업무 상태를 변경하지 않는다는 뜻이다.
엔진 원장 자체가 없는 홈 조회에서는 원장과 `.aicmo` 디렉터리를 만들지 않았다.

## 실제 로컬 실행 증거

`artifacts/real-use-review/today-entry-synthetic-v3/evidence.json`은 실제 localhost Django HTTP 서버와 Chromium의 합성 실행 기록이다.
앞선 v1/v2는 smoke 스크립트의 label/option 선택 오류로 중단되었으며 완료 증거로 사용하지 않는다.

- 온보딩 후 프로필의 리뷰 목적·10분을 읽어 리뷰 카드를 첫 번째로 표시했고 홈에서 엔진 DB가 생성되지 않음을 확인했다.
- 390/1280px에서 카드 세 개를 확인했다. 다섯 소식 종류에서 사실 입력은 비어 있고 시간은 수정 가능했다.
- 키보드 Enter로 소식 없는 날 안내와 생성 진입을 사용했다. 진행 중에는 새 카드가 숨겨지고 새 요청 URL이 기존 작업으로 이동했다.
- 직접 요청한 실행 `web-477cea4b149b441bbe0a8fa3463d3686`은 success로 완료됐다. 실제 확인 체크·최종 검토·ZIP 저장을 수행했다.
- 묶음 SHA-256: `4ca3b2922bf11f5d8420f33c251d60b97d7fe989c6c23c9b60936e3cc012a4f7`.
- ZIP SHA-256: `9faa86f6f79a52ea4c4f12107f9efd64b99f1601241868bdb460aa4e08e01102`.
- ZIP 내부 파일 해시를 재계산했다. 이후 한도를 0으로 설정해 카드와 새 요청 버튼의 차단을 확인했다.
- 온보딩부터 납품·한도 소진까지 화면 14개를 저장했다. 오늘/진입/종류 선택/진행 중/소진 화면을 육안 확인했고 가로 넘침이 없었다.

생성·검토 명령은 합성 stub이다. 이 결과는 실제 공급자 품질·청구·고객 채택·외부 게시·유료 출시를 입증하지 않는다.

## 자동 검사

전체 회귀는 **563 passed, 1 skipped, 537.26초**다 (`artifacts/real-use-review/today-entry-final-tests.log`).
skip은 기존 Windows 파일 symlink 생성 권한 부족 1건이다. 새 가게 설정의 Windows junction 차단은 실제로 검사했다.
이 전체 실행은 공통 quota SELECT에 필요한 열을 명시하는 마지막 보완 전에 시작했으므로 해당 보완의 확정 결과는 별도 집중 검사로 구분한다.
마지막 보완 뒤 새 프로세스의 guidance·quota 전체 집중 검사는 **13 passed, 78.31초**다 (`artifacts/real-use-review/today-entry-final-focused-tests.log`).
독립 최신 Django 11개(9.394초)와 quota 핵심 2개(13.78초)도 통과했다. 최종 reviewer **PASS**이며 보고서는 `artifacts/real-use-review/today-entry-review.md`다.
보고서 SHA-256: `26ac362d023068c66c40967f3447c5568a52f9576603b9fec9ba4c9fb5426e68`.
가게 앱·한도의 앞선 집중 검사는 15 passed(210.64초)였고, 새 Django guidance 사례는 11개이며 pytest에서는 wrapper 하나로 집계한다.
Ruff 전체·basedpyright 전체·Django 배포 설정 검사·migration 일관성·Git diff 검사는 통과했다. 빌드한 wheel에 guidance와 새 홈/작성/작업 템플릿이 포함됨을 확인했다.

## 남은 경계

추천은 목적별 고정 순서이며 실제 사용자의 선호를 학습하지 않는다. 입력 중 소식 종류 링크를 다시 열면 미제출 입력은 보존되지 않으므로 입력 전에 선택한다.
웹 사진·문안 편집/자동저장·보관함·게시 기록·성과 화면은 후속 과제다. 실제 이용 금액과 공급자 비용 상한은 상품 건수와 별개다.
현재 설정을 읽는 편의 기능은 최신 사실이나 법적 동의의 확인 증거가 아니다. 관리자 수준의 동시 파일 교체까지 차단하는 격리 저장소는 제공하지 않는다.

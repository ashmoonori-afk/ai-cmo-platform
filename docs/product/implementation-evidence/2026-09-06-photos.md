# 사용자 제공 사진의 승인·납품 연결

## 한 장 요약

가게 실행팩에 사용자가 제공한 JPEG/PNG 최대 2개를 정규화해 첨부한다.
소식별 실제 첨부 여부를 검증하고, 사진 목록의 해시와 사람의 확인 선언을 승인 기록에 연결한다.
G02는 OPEN이다. 합성 실행의 성공을 실제 사진 권리·모델 품질·가게 사용성·유료 출시 검증으로 세지 않는다.

## 구현과 수정

| 경계 | 현재 동작 |
|---|---|
| 업로드 | 업로드 JSON 안의 폴더 내부 상대 경로만 읽는다. 원본 경로/파일명과 별도 source_sha256 필드는 실행 입력·DB·모델 요청·납품에 전달하지 않는다. |
| 실제 이미지 | Pillow로 JPEG/PNG를 디코딩한다. 20 MiB·2,400만 픽셀·단일 프레임 상한, EXIF 방향 반영, 긴 변 최대 2,048의 새 RGB/RGBA PNG로 저장한다. |
| 저장 | 가게 slug 해시별 폴더의 PNG 해시 주소. 리다이렉트 경로를 거부하고, 읽을 때 크기·해시·정규화 바이트를 다시 검증한다. |
| 소식 연결 | 예전 photo_available boolean만으로 사진 보유를 주장하지 않는다. 실제 선택 목록에서 소식별 provided/unavailable과 고정 안내를 검증한다. |
| 미리보기 | 검증된 PNG를 보여주는 로컬 HTML, escaped caption과 대체 텍스트, 반응형 폭. 픽셀 자동 검수나 권리 인증을 주장하지 않는다. |
| 승인 | 사진이 있으면 --photos-reviewed가 필수다. approvals의 photo_manifest_sha256을 동일 트랜잭션에서 저장된 사진 목록 버전과 대조한다. 기존 DB에는 nullable 열을 추가한다. |
| 편집 | local-pack.json의 유효한 문안만 --accept-edits로 인정한다. 사진 목록을 재해시해 변조를 승인하는 경로를 막았다. |
| 전달 | 승인·재개·최종 gate·완료·export에서 공통 검증. 캡처한 PNG bytes를 ZIP에 쓰고, pack/사진 목록/각 파일 해시를 포함한 bundle 해시로 ZIP 이름을 정한다. |

독립 리뷰의 별도 원본 source_sha256 필드 불필요 노출 지적을 반영해 해당 필드를 제거했다.
이미 정규화된 PNG를 입력하면 원본과 저장 PNG의 바이트 및 SHA가 같을 수 있다. 정규화된 파일의 SHA는 계속 검증 근거로 사용한다.
검토된 파일 형식을 명시하도록 manifest에 PNG를 기록한다. 메타데이터가 없는 정규화 PNG를 다시 인코딩한 바이트와 비교해 추가 payload도 거부한다.
사진 목록 손상은 일반적인 ‘resume first’ 안내보다 먼저 검사해 새 실행이 필요한 이유를 제시한다.

## 실행 증거

PowerShell CLI에서 합성 사진 2개로 --photos-file 입력 → photo-preview → --photos-reviewed 승인 → resume → export-local-pack을 수행했다.
합성 executor와 합성 reviewer를 사용한 실행 연결 검증이다. 실제 모델 호출이나 고객 작업은 아니다.

- 실행: `artifacts/real-use-review/photos-synthetic/`, run `photo-case`, 상태 success.
- 승인/terminal이 참조한 사진 목록 SHA-256: `0e705462e8db39de21a98ce24ed69ad7e717f7cacdb06bd1088bdd1ed52ff446`.
- 묶음 SHA-256: `115051afcddf2b15f743ff979a965296f2643ac257a5805f1e7b351c129c838f`.
- ZIP SHA-256: `83cbe1e0829f4ec52a04d9ab786471cf77fd870b667256355efa44ae729cb053`.
- 각 entry의 SHA, 실제 PNG byte 일치, 승인·terminal 사진 목록 SHA 일치, 원본 이름/경로와 별도 source_sha256 필드 부재를 검증했다. 이 JPEG 표본에서는 원본 SHA도 DB와 사진 목록에 없다.
- 확인 스크립트와 결과는 `artifacts/real-use-review/verify_photo_smoke.py`, `photos-synthetic/verified-smoke.json`이다.
- Chromium 390px/1280px에서 사진 2개 로드·alt·한국어 사용권 안내·가로 넘침 없음을 확인하고 스크린샷을 육안 확인했다. 결과는 `photos-synthetic/preview-check.json`이다. 스크린리더 실제 사용 증거는 아니다.

개발 중 전체 회귀는 541 passed / 1 skipped (337.82초)였다. 이후 추가한 manifest 삭제/변경 검사는 차단되지만 오류 안내 기대값이 달라 2개 실패했고, photo 검증 순서를 앞당겨 안내를 수정했다. 최종 검사는 아래 후속 기록으로 구분한다.

### 최종 검사 기록

- 독립 전체: **545 passed, 1 skipped in 343.09s**. 기존 Windows 파일 symlink 생성 권한 검사만 skip이며 사진 회귀는 실행했다.
- 그 뒤 직접 API에서 client 누락 시 KeyError가 발생하는 것을 재현했다. 공유 사진 검증의 client 조회를 안전한 기본값으로 바꿔 기존 safe ID 오류로 거부하고 회귀 1개를 추가했다.
- 이 마지막 국소 수정 후 구현자 사진 회귀: **31 passed in 24.45s**, Ruff PASS, basedpyright **0 errors / 0 warnings / 0 notes**, diff PASS. 전체 545 수치에 새 회귀 1개를 포함했다고 계산하지 않는다.
- 최종 독립 **PASS**: 마지막 client 가드를 포함한 사진 **31 passed in 33.22s**·Ruff PASS·basedpyright 0/0/0, 실제 ZIP 해시 재계산 일치. G10 D 완료 가능, 남은 필수 수정 없음. 보고서는 `artifacts/real-use-review/photos-review.md`에 보관한다.

## 지원 한계

PNG 정규화는 원본 EXIF/GPS/ICC/텍스트 메타데이터를 제거하며 픽셀 속 인물·번호·명찰을 탐지하거나 지우지 않는다.
색 프로필 제거로 표현이 달라질 수 있고 HEIC/GIF/WebP/애니메이션은 지원하지 않는다. 원본은 사용자 폴더에 그대로 남는다.
처리 한도는 제품의 보수적 경계이며 채널 공식 규격이 아니다. 로컬 저장 PNG의 자동 보관 기한·삭제는 아직 없다.
권리/개인정보 검토는 사람의 선언이다. --photos-reviewed가 실제로 화면을 보았음을 기계적으로 증명하지 않는다.
텍스트 모델에는 PNG bytes/base64를 보내지 않는다. 설명/크기/PNG 해시만 전달하며 실제 픽셀을 검토했다고 표시하지 않는다.
웹 인증·가게 소유권·게시 API·이미 가져간 ZIP 회수는 별도 범위다. 사진 변경은 새 실행과 승인을 요구한다.
사진 단계/SOP의 명세 변경 전 실행은 현재 fingerprint 검증에 따라 새 실행이 필요하며 조용히 소급 변경하지 않는다.

## 다음 단계

1. 개발·reviewer는 최신 전체 회귀·정적 검사·사진 변조 회귀를 대조하고 PR의 SHA를 확인한다.
2. 개발자는 기존 러너를 가게별 업무 앱의 생성·편집·승인·보관함에 연결한다.
3. 운영자는 G02를 OPEN으로 두고 실제 공급자 비용·계약·보관 정책과 고객 사용성 증거를 별도로 준비한다.

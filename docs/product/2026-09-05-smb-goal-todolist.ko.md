## 2. 작업 운영 규칙

- `D` = 저장소에서 개발/문서/합성 테스트로 수행 가능. `H` = 고객 참여·운영자 사업 결정·외부 계약/승인 등 사람의 행동 필요. `D+H`는 로컬 준비와 외부 검증을 구분합니다.
- 크기 **[추정]**: S=0.5–1 인일, M=2–3 인일, L=4–6 인일. H의 모집·심사·관찰 대기시간은 별도입니다. L 작업은 실제 착수 때 구현 가능한 소단위로 나눕니다. 숫자는 견적이 아닙니다.
- 작업마다 **변경 파일 / 동작·화면 / 테스트 명령과 결과 / 검토 판정 / 미확인·외부 승인**을 증거로 남깁니다. 기본 기록 위치는 `docs/product/implementation-evidence/`입니다. 고객 정보와 운영 로그는 비공개 저장소 경로에서 익명 요약만 연결합니다.
- 코드가 없는 조사/설계 작업에는 불필요한 테스트 코드를 만들지 않습니다. 상태·권한·입력·돈 관련 로직에는 깨지는 경우를 잡는 실행 가능한 회귀검사를 남깁니다.
- reviewer PASS 후 체크합니다. WARN은 제한과 후속 작업을 연결하고 해당 단계 출시 조건을 다시 판단합니다. 고객 미참여·결제 미실행·정책 미확정은 완료 증거가 아닙니다.
- 가격·한도·정책 변경은 사용자에게 보이는 문구와 서버 검증을 함께 갱신합니다. 매핑 변경 시 AGENTS/레지스트리/테스트도 갱신합니다.
- 전체 저장소 범위 검사 기준: `python -m pytest -q`, `ruff check src tests examples`, `basedpyright src tests`, `git diff --check`. 환경에서는 `.venv/Scripts/` 실행 파일을 사용할 수 있습니다. 기존 실패를 새 기능의 성공으로 덮지 않습니다.

# 한 장 요약

가게별 월간 실행팩 수와 문안 생성 시도 수를 제한하는 로컬 운영 기능입니다. 운영자는 실제 제공 범위에 맞는 수량을 설정하고, 예약·차감·상품 단위 반환 상태를 확인합니다. 금전 결제나 공급자 청구비를 계산하는 기능은 아닙니다.

## 한도 설정과 확인

아래 4팩·12회는 명령 형식을 보여 주는 합성 예시이며 판매 상품의 확정 수량이 아닙니다. shop과 기간을 실제 운영 설정으로 바꿉니다. 기간은 한국 시간의 달력 월(YYYY-MM)입니다.

```powershell
uv run aicmo quota-set shop --period 2026-09 --packs 4 --draft-attempts 12
uv run aicmo quota shop --period 2026-09
uv run aicmo status pack-01
uv run aicmo usage pack-01
```

quota-set은 기존 한도를 갱신하지만 이미 사용한 생성 시도나 예약·차감 합계보다 낮출 수 없습니다. 사용 기록을 초기화하지 않습니다. 0은 작업을 허용하지 않는 상한이며 무제한이 아닙니다. 현재 월 한도가 없는 관리 가게는 새 작업을 시작할 수 없습니다. 다음 월도 운영자가 명시적으로 설정합니다.

한도 이력이 전혀 없는 가게의 로컬 개발 실행은 unmetered입니다. 실행별 모드는 최초 작업 claim에서 고정되므로 이후 한도 설정으로 이미 진행한 실행을 소급 차감하지 않습니다. 이 기능 도입 전에 실행을 시작한 과거 기록도 소급 차감하지 않습니다. 관리형 제공을 시작하려면 새 실행을 만들기 전에 한도를 설정합니다. 아직 계정 인증이 없는 로컬 CLI이므로 신뢰할 수 있는 운영자만 저장소와 DB에 접근해야 합니다.

quota의 packs는 현재 상태별 실행 수이고, status의 Product는 해당 실행의 상태와 최초 예약월입니다. 현재 월 화면과 과거 예약월의 진행 중 실행을 혼동하지 않습니다. usage는 관측한 논리적 공급자 호출과 토큰이며 상품 단위와 별개입니다. 예상 공급자 비용은 unavailable로 표시합니다.

## 예약·차감·반환 규칙

| 상황 | 상품 단위 | 생성 시도 |
|---|---|---|
| 새 관리 실행 | 첫 작업 claim에서 1팩 예약 | drafts claim 전에 월간 시도 한도 확인 |
| 같은 run 중복 요청 | 같은 예약 재사용 | 실제 lease 획득자만 증가 |
| 사장님 승인 대기 | 예약 유지, 차감 전 | 대기 중 resume는 추가하지 않음 |
| 승인·최종 semantic PASS·현재 명세/해시 검증 완료 | 실행 성공과 같은 DB 트랜잭션에서 1회 차감 | 이미 발생한 횟수 유지 |
| 실패·취소 또는 정상적인 WARN/demo 완료 | 예약 상태만 해제 | 발생한 횟수 복원 안 함 |
| 같은 달 실패 재시도 | 어느 단계부터 재개하든 한도를 확인하고 재예약 | 실제 drafts를 다시 시작할 때만 추가 |
| 성공한 실행의 파일 재생성 | 기존 차감 유지, 재차감 없음 | 실제 drafts 재생성은 추가 시도 |
| 만료된 월의 해제된 실행 재시도 | 새 실행 요구 | 기존 월 기록 보존 |

승인 대기가 다음 달로 넘어가도 예약월은 바뀌지 않습니다. 최초 예약월의 한도에서 완료합니다. 프로세스가 종료되면 예약을 자동 만료시키지 않습니다. 실행 증거를 확인하고 resume로 재개하거나 cancel로 해제합니다. 자동 만료 후 살아 있는 실행이 이중 차감하는 상황을 피하기 위한 로컬 운영 계약입니다.

draft-attempts는 drafts 단계의 실행권 획득 횟수입니다. 공급자 호출 직전 프로세스가 종료되거나 입력 문맥 검증에 실패해도 해당 시도는 소비된 상태로 남습니다. stale lease를 재획득하면 새 시도이며, 같은 팩 예약을 재사용합니다. 일반 엔진의 단계당 최대 3회 제한도 적용됩니다. 리뷰·형식 복구·SDK 내부 재시도·토큰·금전 예산 전체를 이 숫자로 제한하는 것은 아닙니다.

한도 부족은 모델 호출 전에 step/run을 failed로 기록합니다. 해당 거부 자체로 단계 시도는 늘리지 않습니다. 한도를 조정하거나 불필요한 예약을 취소한 다음 기존 실행을 resume할 수 있습니다. 상품 차감 이후의 재생성 실패는 기존 차감을 되돌리지 않습니다.

## 상품 단위 반환과 장애 복구

```powershell
uv run aicmo cancel pack-pending
uv run aicmo quota-credit pack-01 --reason "운영 지원 정책에 따른 상품 단위 반환"
```

quota-credit은 성공해 차감된 실행의 상품 단위를 한 번 반환하고 사유를 기록합니다. 금전을 환불하지 않고 공급자 비용이나 생성 시도를 되돌리지 않습니다. 같은 명령을 다시 보내도 추가 반환은 없습니다. 반환한 실행은 resume·재생성을 금지하므로 추가 작업은 새 실행으로 만듭니다. 기존 납품 파일을 삭제하거나 이미 전달한 파일을 회수하지 않습니다.

모든 단계가 완료된 뒤 실행 성공 저장 직전에 중단된 경우에는 cancel 대신 resume로 마지막 검증과 차감을 마무리합니다. DB 트랜잭션 실패는 실행 성공과 상품 상태를 함께 되돌립니다. 변조·명세 변경·불일치 해시는 납품 차감 증거가 될 수 없습니다. SQLite와 로컬 파일은 서로 다른 저장소이며 비협조적인 직접 파일/DB 편집이나 운영자 권한 관리를 해결하는 기능은 아닙니다.

## 다음 단계

1. 운영자는 새 가게의 첫 관리 실행 전에 합의한 기간·수량을 설정하고 예약/차감 상태를 확인합니다.
2. 개발자와 reviewer는 실제 공급자 usage·가격 근거·청구 대사와 계정 권한이 연결될 때 G09의 남은 범위를 별도 검증합니다. G02는 OPEN입니다.
